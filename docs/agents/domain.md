# 域文档（Domain Docs）

说明工程技能在探索代码库时，应如何消费本仓库的域文档。

## 探索之前，先读这些

- **`GLOSSARY.md`**（仓库根目录），或
- 若根目录存在 **`GLOSSARY-MAP.md`**：它指向每个上下文各自的 `GLOSSARY.md`，按需读取相关条目。
- **`docs/adr/`**：阅读涉及你即将改动区域的 ADR。若是多上下文仓库，还要检查 `src/<context>/docs/adr/` 里的上下文级决策。

如果这些文件不存在，**静默继续**。不要指出它们缺失，也不要主动建议先创建。`/domain-modeling` 技能（经由 `/grill-with-docs` 与 `/improve-codebase-architecture` 触达）会在术语或决策真正被确定时再懒创建它们。

## 文件结构

单上下文仓库（本仓库即为此类）：

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-....md
│   └── 0002-....md
└── src/
```

多上下文仓库（根目录存在 `GLOSSARY-MAP.md` 时）：

```
/
├── GLOSSARY-MAP.md
├── docs/adr/                          ← 系统级决策
└── src/
    ├── <context>/
    │   ├── GLOSSARY.md
    │   └── docs/adr/                  ← 上下文级决策
    └── ...
```

## 使用术语表的词汇

当你的输出要给某个域概念命名（issue 标题、重构提案、假设、测试名）时，使用 `GLOSSARY.md` 里定义的术语。不要漂移成术语表明确回避的同义词。

如果你需要的概念还没进术语表，这是一个信号：要么你在发明项目并不使用的说法（应重新考虑），要么确实存在缺口（记下来留给 `/domain-modeling` 处理）。

## 标记与 ADR 的冲突

如果你的输出与某个已有 ADR 相矛盾，应显式提出，而不是静默覆盖：

> _与 ADR-0007（事件溯源订单）相矛盾，但值得重新讨论，因为……_
